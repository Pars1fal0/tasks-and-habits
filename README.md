# Ритм дня

Трекер задач и привычек на русском языке. Работает как PWA в браузере и как десктопное приложение на Electron. Данные хранятся local-first в `localStorage`, а при настройке Supabase могут дополнительно сохраняться в удаленную Postgres-БД.

Веб-версия подготовлена для автоматической публикации в Cloudflare Workers Static Assets после каждого push в `master`.

## Возможности

- задачи на выбранный день с дедлайном, временем, приоритетом, категорией и напоминанием;
- быстрый ввод задач: `Позвонить врачу завтра 10:00 #здоровье !high`;
- более умный быстрый ввод: `через 2 часа`, `в следующий понедельник вечером`, даты вида `15 июля`;
- повторяющиеся задачи: каждый день, каждые 2/3 дня, будни, выходные, неделя, месяц, год;
- настраиваемые повторы: выбранные дни недели, конкретное число месяца, каждые N дней;
- исключение конкретного дня у повторяющихся задач;
- просроченные задачи отдельным блоком;
- перенос задач: на завтра, на следующую неделю, на выбранную дату, на сегодня из просроченных;
- undo в toast для опасных и быстрых действий;
- цели со сроком, собственными переставляемыми чекпоинтами, автоматическим прогрессом и историей достижений;
- выбор области изменения времени повторяющейся задачи в таймлайне: один день или этот и последующие;
- обратимое расписание: временной блок можно вернуть в режим без времени через форму, меню или drag в таймлайне;
- привычки с галочкой или числовой дневной целью;
- настраиваемые повторы для привычек: выбранные дни недели, число месяца, каждые N дней;
- счетчик серии привычек;
- дневной список, недельная доска, месячный календарь и обзор прогресса за неделю, месяц или год;
- перетаскивание задач между датами в недельном и месячном календаре;
- раскрытие скрытых задач в месяце через `+N`;
- поиск и фильтры по задачам и архиву;
- архив завершенных задач с поиском, фильтрами за 7/30/90 дней, массовыми действиями и безопасным удалением отдельных повторов;
- сворачиваемая история старых невыполненных задач и пропущенных повторов;
- экспорт и импорт JSON;
- локальный авто-бэкап и восстановление из последнего экспорта;
- safety backup перед импортом JSON, чтобы не затереть последнее хорошее состояние;
- файловый авто-бэкап в Electron в `Documents/Ритм дня/backups`;
- синхронизация между устройствами через Supabase Auth: автосохранение, проверка каждые 30 секунд, объединение конфликтов и локальная история операций;
- фоновые напоминания в Electron, пока приложение работает в трее.

## Структура

- `index.html` — разметка приложения и шаблоны карточек.
- `styles.css` — стили интерфейса.
- `app.js` — главный координатор состояния и событий.
- `app-utils.js` — общие чистые утилиты дат, времени, текста и цветов.
- `calendar-view.js` — недельная доска, месячный календарь, heatmap, метрики выбранного периода и drag по датам.
- `archive-view.js` — архив завершенных задач, массовые действия, восстановление и удаление отдельных записей.
- `form-dialog.js` — доступное поведение мобильных и планшетных форм: focus trap, Escape и возврат фокуса.
- `tasks-view.js` — рендер задач, просрочки, исключенные повторы и действия карточек задач.
- `habits-view.js` — рендер привычек, серии, галочки и числовые цели.
- `goal-checkpoint-editor.js` — добавление, переименование, удаление и сортировка чекпоинтов цели.
- `goals-view.js` — карточки целей, прогресс и состояние достижения.
- `task-moves.js` — переносы и безопасное разделение повторяющихся серий по выбранной области изменений.
- `task-form.js` — форма создания и редактирования задач.
- `task-schedule.js` — режимы без времени, дедлайна и временного блока, включая быстрые пресеты.
- `habit-form.js` — форма создания и редактирования привычек.
- `quick-input.js` — парсер быстрого ввода.
- `recurrence.js` — правила обычных и настраиваемых повторов.
- `remote-sync.js` — синхронизация состояния с Supabase/Postgres через REST API.
- `remote-auth.js` — вход, регистрация, восстановление пароля и обновление отдельной локальной Supabase-сессии.
- `device-sync-controller.js` — фоновая проверка изменений при работе на нескольких устройствах, возврате в приложение и восстановлении сети.
- `planning-history.js` — история старых пропусков и периоды архива.
- `state-normalizer.js` — нормализация импортированных и сохраненных данных.
- `storage.js` — чтение, запись, UI-состояние и локальные бэкапы.
- `task-moves.js` — перенос задач между датами и безопасное разделение повторяющихся серий.
- `toast.js` — toast и кнопка undo.
- `sw.js` — service worker для PWA-кеша.
- `desktop/` — Electron-оболочка, preload, файловые бэкапы и smoke-тест.
- `CHANGELOG.md` — заметки об изменениях.
- `supabase-schema.sql` — SQL для таблицы удаленного хранения состояния.

## Удаленная БД

1. Создать проект Supabase.
2. Открыть SQL Editor и выполнить `supabase-schema.sql`.
3. В приложении открыть `Настройки` → `Данные`.
4. В раскрываемом блоке указать `Supabase URL` и публичный `anon key`.
5. Зарегистрироваться или войти по email, затем включить `Удаленная БД`.
6. Нажать `Сохранить в БД` для первой выгрузки. После этого обычные изменения будут автоматически отправляться в БД.
7. На втором устройстве указать тот же Supabase URL и anon key, войти в тот же аккаунт и включить синхронизацию. Изменения проверяются каждые 30 секунд и при возврате в приложение.

Сессия аккаунта хранится отдельно на устройстве и не попадает в JSON-экспорт или удаленный `ui_state`. Старый доступ по приватному ключу оставлен только для совместимости.

`Загрузить из БД` заменяет локальное состояние удаленным, но перед этим создает safety backup.

## Запуск в браузере

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

Затем открыть `http://127.0.0.1:5173/`.

## Публикация сайта

Cloudflare Workers подключается к приватному GitHub-репозиторию и автоматически публикует каждый push в `master`. Параметры проекта:

- production branch: `master`;
- build command: `npm run build:cloudflare`;
- deploy command: `npx wrangler deploy`;
- root directory: оставить пустой;
- static assets directory задается в `wrangler.jsonc` как `web-dist`.

Команда публикации сначала запускает unit-тесты и lint, затем собирает чистый статический каталог `web-dist`. Для корректных ссылок подтверждения email полученный адрес `*.workers.dev` нужно указать в Supabase в `Authentication` → `URL Configuration` как `Site URL` и добавить в `Redirect URLs`.

## Десктопная версия

Установить зависимости:

```powershell
npm install
```

Запустить отдельное окно:

```powershell
npm run desktop
```

Запустить smoke-тест:

```powershell
npm run desktop:smoke
```

Запустить быстрые unit-тесты бизнес-логики:

```powershell
npm test
```

Запустить настоящий Electron E2E для мобильной формы и таймлайна:

```powershell
npm run test:e2e
```

Собрать Windows-версию:

```powershell
npm run build:win
```

Готовые файлы появятся в папке `dist`.

## О миграции на фреймворк

Перенести приложение на фреймворк можно. Самый разумный путь — не переписывать все сразу, а сначала отделять чистую бизнес-логику от DOM. Первый шаг уже сделан: быстрый ввод, переносы задач и toast вынесены из `app.js`.

Если делать полноценную миграцию, хорошие варианты:

- React + Vite — лучший выбор, если нужен компонентный интерфейс, тесты и дальнейший рост.
- Svelte + Vite — проще и легче для небольшого локального приложения.
- Vue + Vite — тоже хороший вариант, если нравится декларативный шаблонный стиль.

Для этого проекта я бы выбрал Svelte или React. Svelte даст меньше кода, React даст больше экосистемы.
